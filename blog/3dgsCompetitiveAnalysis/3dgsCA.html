Bottom line

3D Gaussian Splatting is moving from research demo to production tool — but the experience is still fragmented. Tencent's Hunyuan chose the Mesh route while still emitting 3DGS points; everyone else races on mesh generation; and the dedicated splat tooling (capture → train → clean → export) is split across local / cloud and mobile / desktop. The open gap is one legible, end-to-end surface for professional users.

00Overview

What this page is, and how it is structured

This is a competitive read of the public 3DGS landscape as of 2025–2026, written while preparing for a 3DGS experience-design role. It is split into two parts: Part 1 covers AI-generated 3D / 3DGS products (what gets made), and Part 2 covers the 3DGS modelling and model-processing platforms (how splats are actually captured, trained, cleaned and shipped) with an interface-level lens.

3DGS in plain words

Imagine filming a chair from every angle for a few seconds, then turning that video into a 3D scene you can walk around in on your phone — photo-real, light to load, and no 3D-modelling skills needed. That is roughly what 3DGS does. The "Gaussian splat" is just the technical name for the tiny fuzzy dots it uses to paint the scene. Why people care: until now, making 3D meant hiring a 3D artist; 3DGS + AI lets almost anyone capture or generate 3D and drop it into apps, games or the web. The rest of this page explains who is building the tools for that.

Method & honesty note

Findings are drawn from publicly available product pages and reviews, not from hands-on benchmarking. The interface sketches below are schematic illustrations (how each tool's UI is laid out), not pixel-accurate screenshots. Where a figure is vendor-reported it is labelled as such. This page is a design research artefact, not a shipped product — the same framing used for the 3DGS pipeline study.

01Part 1 — AI-Generated 3D / 3DGS Products

What gets made: generation vs reconstruction

Two routes coexist. Generative tools take text or an image and return a mesh (Tripo, Meshy, Rodin, Stable-Fast-3D). Reconstruction tools take photos / video and return either a mesh or a radiance field — Tencent's Hunyuan WorldMirror is the notable case that emits both 3DGS points and a standard mesh from one forward pass. The practical truth across all of them: none replaces a 3D artist, and every output still needs retopology, UV, material and engine prep before it is production-ready.

Tencent Hunyuan3D (WorldMirror)

You hand it a photo or a short video; in one go it returns a 3D model you can spin 360°. Meshy
Text / image → textured mesh · $16–20 / mo
Same idea as Tripo, but it leans hardest into textures and plugins. It connects straight into Blender, Unity and Unreal, so game and product designers can pull models in without leaving their tools. Best for: textured, game-ready assets.

High-fidelity generation · $99 / mo
The "pro" tier. It produces the highest-detail, most realistic 3D characters and objects, but it is slower (minutes) and pricey. Best for: when quality matters more than speed.

Not text-to-3D — instead you capture a real object or place with your phone, and it turns that into a photoreal 3D scene. Think "3D photo" of your sofa or a room. Best for: digitising real things you already have.

What this means for a 3DGS tool designer

The differentiator is no longer "can it generate" — it is the post-generation experience: cleanup, format, the engine handshake, and iteration speed. Whoever makes the messy middle legible wins professional users. That is exactly the gap the next end-to-end 3DGS platform is positioned to close.

02Part 2 — 3DGS Modelling & Processing Platforms

Interface competitive analysis of the splat toolchain

These are the tools that actually handle Gaussian splats end-to-end. They split by where the work happens — on-device, cloud, or desktop — and by how much of the pipeline they wrap in a single surface. The workflow below is shared by all of them, and the pain points are remarkably consistent.

02·aEach tool, in plain words

Interface sketch (left) + what it actually does (right) — no jargon
Polycam
Web + mobile · cloud-based · subscription
The friendly front door. You scan with your phone or upload photos; it builds a 3D point-cloud you can measure and view. Cloud-based, so it is easy but your data leaves the device. Best for: quick, shareable scans.
Luma AI
Mobile + cloud · freemium
Here Luma is used for capture: film a real object or room and it reconstructs a photoreal 3D scene in the cloud. Simple to start, but each scan can take 20–30 minutes to process. Best for: turning real places into 3D.
KIRI Engine
Mobile + cloud + Blender · €90 / yr for 3DGS
Capture anywhere (phone, web, Blender) and it gives you both the splat and a mesh, with a clever "brush" to wipe away unwanted background before upload — saving time and cloud cost. Best for: cleaning as you go.
PostShot (Jungle)
Windows desktop · local (NVIDIA) · paid
The power-user's desktop tool. It does the whole "align photos → train the 3D → preview live" in one window, with sliders to tune quality. Needs a strong NVIDIA GPU. Best for: maximum control on a strong PC.
SuperSplat (PlayCanvas)
Web browser · free
A free, browser-based viewer / editor for splats. You load a 3DGS file and manually click to delete junk (stray dots, floaters) — no install needed. Best for: light clean-up without software.
Scaniverse (Niantic)
iPhone (LiDAR) · local · free
Niantic's iPhone app using the built-in LiDAR sensor. Point your phone at a room or object and it builds a 3D scan on-device, instantly. Best for: fast real-world capture on iPhone.
CloudCompare / MeshLab
Desktop · local · free
The "spreadsheet" of 3D points. Free desktop tools to open, filter, clean and convert massive point clouds. Ugly but powerful. Best for: heavy data wrangling.

  • Local vs cloud is the first UX decision. PostShot, SuperSplat and Scaniverse keep data private and near-instant; Polycam, Luma and KIRI lean cloud for quality.
  • "One-UI completeness" varies sharply. PostShot does align → train in a single window (best for beginners); the others stitch mobile capture + cloud + a desktop editor.
  • On-device first-pass cleanup is a smart pattern. KIRI's Sphere / Plane / Brush and Scaniverse's crop clean before upload and cut cloud cost 30–40% — design that respects the user's bandwidth and bill.
  • The editing metaphor differs. SuperSplat = browser select-delete; KIRI = Blender-native Edit / Render toggle; PostShot = training-time parameters. None yet offers consumer-level semantic cleanup (e.g. "remove all people").
  • Export fragmentation is a real pain. PLY is not a uniform standard; SuperSplat / PostShot re-saving fixes compatibility. The format → engine handshake is still manual.
Implications for 3DGS experience design

The unmet need is a legible end-to-end surface where a professional moves capture → trained splat → cleaned asset → engine-ready export without leaving the product or learning four tools. Design against the six consistent pain points above: capture thresholds (overlap / lighting), training black-box + OOM, no auto-clean, format sprawl, and no publish QA checklist. This is precisely the gap the next 3DGS platform can close by turning the analysis into a single coherent interface.

03Takeaways

What a 3DGS experience designer should act on
  1. Route clarity. Decide Mesh-default vs 3DGS-default per use case; do not force one representation on every workflow.
  2. The win is in the messy middle. Cleanup, export and the engine handshake — not generation — are where professional users lose time today.
  3. One coherent surface beats a toolchain. On-device pre-clean + cloud train + in-app edit is the pattern to beat.
  4. Design for semantic operations, not just geometric ones. "Remove all people" beats "delete these 400 splats" — the next leap is intent, not more sliders.
