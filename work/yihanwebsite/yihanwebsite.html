Yihan's New Portfolio Website
Bottom line

After years on a Hugo static framework — a solid blogging experience with very little creative room — I rebuilt my online presence from scratch in HTML, CSS and JavaScript, hosted on GitHub Pages. The project is unusual in one respect: the page you are reading is the deliverable. Every component on this site is the outcome described below.

00Executive Summary

What this project is, and why it works

The previous site ran on a Hugo static web framework. It offered a solid blogging experience but limited creative flexibility, so the replacement was built entirely from scratch with HTML, CSS and JavaScript and hosted on GitHub Pages — which gave the freedom to create a more interactive, more engaging and more visually distinctive experience.

  1. The rebuild was driven by an audit, not by taste. The old home and work pages were reviewed first and their specific failures written down — missing information, no interactivity, no visual elements, navigation that required repeated clicks, no responsiveness, and too much scrolling for the content it carried. Each optimised element on the new site answers a named limitation.
  2. Interactivity was added where it does actual work. The self-introduction became a stylised, interactive piece, recent projects moved into filter tabs presented as a carousel, and interactive visual elements were introduced across the page — so the visitor handles the content instead of reading past it.
  3. Readability was treated as a layout problem, not a typography one. The old work page's main weakness was excessive vertical scrolling; the new one holds visual unity with the home page while navigating information through tabs, so the same content occupies far less depth without losing any of it.
  4. Responsiveness was specified rather than left to chance. Seven states — home, menu, work and project page on mobile; home, work and project page on desktop — were designed individually, which is what keeps the mobile experience from being a compressed desktop one.

01Design Perspective

Discipline: layout & information design

Both core pages were judged against the old versions rather than in isolation, and the findings were recorded as limitations before any new layout was drawn. That record is what the redesign is accountable to.

Home — limitations Lacked some information · lacked interactivity · lacked visual elements · navigation required repeated clicks.
Home — optimisation Stylised interactivity on the self-introduction · recent work projects added with filter tabs presented as a carousel · interactive visual elements introduced · clear information navigation kept.
Work — limitations Lack of responsiveness across devices · too much “scrolling down”, which reduced readability.
Work — optimisation Maintains visual unity with the home page · simple and interactive information navigation · effective responsiveness design.
Methodology

Each limitation was paired with a specific remedy of the same granularity — “lack of visual elements” became the illustrated self-introduction, “need clicks for navigation” became filter tabs, “too much scrolling” became the tabbed work grid. Keeping the audit at this level of detail is what prevents a redesign from becoming a restyling: every change can be pointed back at something a visitor actually lost.

Home page — the previous version and its recorded limitations, beside the new page and the optimisations applied against them.
Work page — the old vertical project list, whose length was its own weakness, beside the tabbed grid that carries the same projects in a fraction of the depth.

02Technical Perspective

Discipline: front-end implementation & responsive design

The site is hand-written: HTML, CSS and JavaScript with no framework and no build step, deployed directly from the repository to GitHub Pages. That choice is what removes the constraint the previous framework imposed — every interaction on these pages is code I control, rather than a theme option.

Responsive state 01

Home

Desktop and mobile are designed separately, so the mobile home keeps the self-introduction's interactivity rather than dropping it for space.

Responsive state 02

Menu

A dedicated mobile menu state, since the desktop navigation has no equivalent at narrow widths.

Responsive state 03

Work

The project grid is specified for both breakpoints, which is where the old page's scrolling problem was solved.

Responsive state 04

Project page

A template state for every case study — category, content and year held in a consistent header so that the 12 project pages read as one system.

Interaction

Filter tabs & carousel

Client-side filtering and a carousel over recent work, so a visitor can reach any project without travelling down the page.

Delivery

GitHub Pages

Static hosting straight from the repository — no server to maintain, and the bilingual English/Chinese structure served from one deployment.

Responsive specification — the mobile states (home, menu, work, project page) and their desktop counterparts, designed individually rather than derived by compressing one into the other.

03Design System

Discipline: typography & colour system
Design system — one type family (Montserrat Alternates with Montserrat) at three heading sizes for desktop and their mobile counterparts, alongside the full colour set and its 60 / 30 / 10 distribution.
Type Montserrat Alternates with Montserrat — a single family carrying headings 1–3, so the site's voice stays constant from the home page into every case study.
Colour Five values: #224055 navy, #8FC4D2 accent blue, #191D20 near-black, #FFFFFF white, #FFB9A6 peach.
Ratio 60 / 30 / 10 — near-black for 60% of the surface, navy for 30%, accent blue for 10%. Holding this ratio is what keeps the accent colour reading as an accent across twelve different project pages.
Scale Desktop and mobile type scales are specified independently rather than scaled proportionally.
Why the system matters more than any single page

Each project page carries its own palette — a board-game platform, a VR service, a robotic performance. The site's own system has to sit underneath all of them without competing, which is exactly what the 60 / 30 / 10 ratio and the single type family are for: the chrome stays quiet so the work can be loud.

While this platform highlights recent work, the former site still houses some archived projects.
